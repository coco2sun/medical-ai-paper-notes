01 · Executive summary

它不是“医学版聊天框”，而是一套临床工作台

OpenEvidence 的核心是一个会调度医学检索、指南、计算器、许可内容和工作流工具的临床任务入口。问答只是表层，背后还有患者上下文、Visit 文书、计费、CME、团队协作和患者通信。

输出 8 个章节、比较表、证据局限和病人级建议。

自然语言检索后按疾病、阶段、招募状态与地点展示。

结论：产品真正的护城河是“医学任务编排 + 许可知识源 + 可交互工具 + 临床上下文 + 输出落地”，而不只是生成一段文字。

03 · Ask

Ask：从一句问题到可核查的临床答案

输入层

  • 文本问题与自然语言病例
  • 录音输入与双向 Voice Mode
  • PDF、图像、化验单等附件
  • 患者选择后继承既往问题、Visit 与上下文
  • 快捷建议题，降低空白页启动成本

任务模式

  • Clinical Decision Support：默认综合问答
  • Paperwork：先授权、保险申诉、患者材料
  • Calculators：量表、评分、剂量与公式
  • Guidelines：学会指南和更新摘要
  • Drug Safety：相互作用、剂量、禁忌与不良反应

标准回答的组成

查询分析状态 → 证据检索 → 结论 → 指南/研究证据 → 可交互计算器或图表 → 关键不确定性 → 参考文献 → 推荐追问。

Deep Consult 的组成

较长的后台研究过程，最终生成分章节报告、比较表、量化证据、冲突证据、证据强度/局限、患者级建议与大规模参考文献。

答案后的折叠与可选功能

内容操作

Helpful / Not helpful、复制文本、复制为图片、加入 Collection；表格支持 Export，图像支持全屏查看与反馈。

继续工作

推荐 Follow-up Questions；输入区 More options 可重新挂载附件或 Dotflow；可切换语音/录音。

证据下钻

References 可展开/折叠；单篇文献有 Summary；来源标注 Guideline、RCT、SR、Review、Opinion、Recent 等类型。

分享权限

默认 Private，可按人名/邮箱授权；Public 允许持链接者访问，并显著提示先确认没有 PHI 或敏感医疗信息。

EvidenceGrade™ 是什么？
官方 User Guide 说明：答案顶部的 EvidenceGrade 提供证据强度的快速判断，点击后展示为什么升/降级的依据。它位于“结论”和“参考文献”之间，承担证据质量解释层。
Voice Mode 与普通录音有什么区别？
普通 Record 更像语音转文字输入；Voice Mode 是实时双向对话，会把简洁、适合听取的证据型答案朗读出来，同时保留完整文字记录与引用。
04 · Test cases

四个虚构案例，验证四种产品能力

标准问答自动计算器指南

案例 A：房颤患者抗凝评估

58 岁女性，非瓣膜性房颤、高血压，无卒中/TIA、糖尿病或血管病，肾功能正常。计算 CHA₂DS₂‑VASc，并解释是否考虑抗凝。

实测结果：
  • 系统识别年龄、性别、高血压等变量，自动运行并展示可交互 CHA₂DS₂‑VASc 计算器。
  • 得分 2；给出约 2.2% 缺血性卒中年风险和 2.9% 卒中/TIA/系统栓塞风险。
  • 结合 2023 ACC/AHA/ACCP/HRS 指南说明女性性别是风险修饰因素；把患者归于中间风险，建议共同决策。
  • 继续补充图表、关键不确定性、3+ 篇参考文献和来源标签。
Deep Consult30 references8 sections

案例 B：RA 患者围手术期用药

62 岁 RA 女性，使用每周甲氨蝶呤和每两周阿达木单抗，计划全膝关节置换；要求分析停/启药、感染与复发权衡、肾损伤/活动性感染变化，以及证据局限。

实测结果：
  • 后台先显示“Researching medical literature”，耗时明显长于标准模式。
  • 报告分 8 节：范围、逐药建议、感染/复发权衡、肾功能、活动性感染、指南差异、证据局限、患者建议。
  • 输出多张比较表：甲氨蝶呤继续；阿达木单抗按给药周期停用，最后一针后第 3 周手术，约术后 14 天且伤口愈合再启。
  • 引用 ACR/AAHKS、澳大利亚指南、Cochrane、RCT、观察研究和 FDA 标签，共 30 条；主动指出“生物制剂无 RCT、Meta 分析结论冲突”等局限。
Drug Safety机制 + 严重度

案例 C：Paxlovid 与心血管用药相互作用

68 岁房颤患者使用 apixaban 5 mg bid、atorvastatin 40 mg，CKD 3 期，拟用 nirmatrelvir/ritonavir。

实测结果：
  • 把问题拆成 apixaban、atorvastatin 两个高价值相互作用和 Paxlovid 肾功能剂量。
  • 解释 CYP3A4/P‑gp 机制；给出 apixaban 暂减至 2.5 mg bid、statin 暂停/降剂量等具体管理路径。
  • 引用 JACC 综述、FDA 标签和房颤指南，并插入心血管药物相互作用图。

05 · Visits

Visits：把“问证据”延伸到整次就诊

Visits 的核心对象不是对话，而是 Patient × Visit × Note。系统在同一屏完成采集、文书、证据问答、患者摘要和编码建议。

1. 选患者 / 排程患者保存长期上下文；日历可 Today、Schedule Visit、Subscribe。
2. 会前准备Pre-chart、选择 SOAP 与 AVS 模板、Voice、Telehealth。
3. 采集就诊Record / Transcribe、Running Notes、Raw Transcript、问答建议。
4. 生成与编辑结构化 Note、富文本、逐节复制、修改模板、AVS。
5. 落地与复用CPT / E&M / ICD‑10、历史、患者上下文、Care Team。

Visits Home

四个 Tab：Calendar、Patients、Templates、Visit History；另有 Visit settings。Patients 支持搜索、排序、置顶、网格/列表。

Patient 作为上下文容器

页面明确说明：在患者选中状态下发起的问题和 Visit 都能访问该患者的全部上下文，实现跨时间连续性。

模板系统

默认 SOAP、AVS、H&P、ED Note、Consult Note；富文本编辑器支持标题、列表、任务、表格。[] 是 AI 填充占位，@@...@@ 保留原文，() 写局部指令。

Voices

Specialty Focused、Detailed、Concise、Narrative 四种内置风格，也可 New Style。它控制生成文书的语气、颗粒度和筛选范围。

Visit 内置 Ask

能基于当前 Visit 询问“还有什么问题要问”“检查计划禁忌”“用证据增强计划”；History 保留本次就诊内问题。

Billing 与 AVS

文书完成后生成 E/M、CPT、ICD‑10 和 MDM 理由；AVS 以患者友好语言生成，可编辑、分享并有独立默认模板。

Care Teams

共享患者、Visits 与文档；Personal 空间仍私有。Clinician 可录音和签署，Care Coordinator 无需 NPI、负责外围流程，Owner/Admin 管权限并保留审计逻辑。

同意与远程医疗

开始采集前明确提示依法律取得录音同意/告知；Telehealth 是可选开关。录音/麦克风属于权限敏感动作。

06 · Tools

工具与扩展能力

Medical Calculators

目录显示 213 个计算器，支持搜索；计算器自身可交互，并提供“Ask OpenEvidence to interpret this”把结构化结果送入问答。

Collections

把问题归组；支持搜索、新建和在答案操作区直接加入。它是个人知识整理层，不改变原始对话。

Clinical Trials

自然语言解析 condition / phase / location，搜索美国活跃试验；提供卡片、地图、排序、筛选和详情。

Dotflows

类似 EHR dot phrase，但不是粘贴静态文本，而是把保存的自然语言指令送给模型；输入 . 触发，也可设为默认。

Patient Messaging / Dialer

移动端用医院/诊所号码呼叫，Web/移动端发送短信并可允许回复；隐藏个人号码。首次使用需接受 Telehealth Policy 并完成 opt-in。

Fax

专属 OpenEvidence 传真号码，可上传、扫描或拍照发送并收件；同属 Dialer opt-in，未开通前停留在 Get started 门槛。

08 · Product logic

研发视角：一次任务怎样流经系统

上下文装配账户、患者、Visit、附件、历史、选择的模式/Dotflow。
意图与任务路由临床问答、指南、药安、文书、计算器、试验、Deep Consult。
检索与工具调度许可全文、指南、PubMed/FDA、计算器、registry、地图数据。
证据合成结论、量化结果、冲突、局限、参考文献、EvidenceGrade。
结果落地追问、导出、Collection、Note/AVS、Billing、CME、分享。

1. “模式”更像路由提示，不是五个独立聊天机器人

同一输入框和回答框架不变，但推荐案例、工具优先级、答案结构发生改变；Drug Safety 会优先组织机制/严重度/管理，Paperwork 会优先输出文书。

2. 计算器是模型可调用工具

房颤案例证明模型能从自由文本抽取变量、回填计算器、展示可编辑状态，再引用结果进行指南解释。这是“LLM → tool → LLM”的闭环。

3. Deep Consult 是异步研究管线

先进入独立“Researching medical literature”状态，完成后一次性呈现分节报告和大量来源；与标准流式回答的耗时、规模和证据审计深度不同。

4. Patient 与 Visit 是长周期状态

对话是短周期任务；患者保存跨对话上下文，Visit 聚合某次就诊的录音、Note、AVS、编码和问答。团队则在此之上增加共享边界和角色。

5. 输出组件是结构化的

答案里的表格、图、学会材料、引用、来源类型、按钮都不是纯 Markdown 文本，而是可交互 UI 组件，便于导出、下钻和反馈。

6. 教育与增长复用同一数据

历史问题被转成 CME 主题；社区 Dotflows 和 Visit 模板反过来降低任务输入成本，形成“使用 → 沉淀 → 复用 → 教育”的循环。

可推断的核心领域模型： User / Clinician、Patient、Conversation、Visit、Template、Voice、Dotflow、Collection、Evidence Source、Calculator Run、Trial、CME Topic、Team、Message/Fax。它们通过权限、上下文和任务执行记录关联。

10 · Safety & privacy

隐私、同意与高风险动作边界

默认最小暴露

对话默认 Private。公开分享前明确提醒：任何拿到链接的人都能查看，必须先移除 PHI 和敏感医疗信息。

录音需要法律同意

Visit 页面在 Transcribe/Pre-chart 附近持续显示同意提示；麦克风授权、真实录音和患者信息处理都应由用户主动确认。

通信需要 opt-in

Messaging/Fax 的 Get started 会接受 Telehealth Policy 并可能开通专属号码，这是账户层外部能力，不应在探索阶段替用户点击。

角色与边界

Care Coordinator 可以支撑流程，但不能录制或签署临床文书；Clinician、Owner/Admin 拥有不同权限。

11 · Findings

实测发现、未执行动作与使用建议

测试影响：本次创建了 3 个虚构案例对话，并因点击 Pre-chart 产生一条空的“Visit on Jul 31”记录；没有发送短信/传真、没有公开分享、没有申领 CME、没有创建团队或患者。

表现亮点

  • 自由文本到计算器的自动工具调用自然、可核对
  • 参考文献类型、指南卡片与许可图表非常丰富
  • Deep Consult 会主动陈述证据冲突和局限
  • 问答、Visit、CME、模板与团队形成闭环

需要留意

  • Deep Consult 明显更慢，应提供进度、取消与后台完成通知
  • 功能入口多，Tools、全局菜单、主页模式存在分散
  • Community、Dialer/Fax 首次进入有独立 setup/opt-in
  • CME Claimed 实测出现 1/1/1970 日期，可能是占位或数据异常，值得研发核查

新用户上手顺序

  1. 先用标准 Clinical Decision Support 问一个具体病例
  2. 展开 References 和 Summary 学会核查
  3. 再试 Calculator / Guideline / Drug Safety 模式
  4. 复杂争议问题才使用 Deep Consult
  5. 高频格式沉淀为 Dotflow；患者连续工作转入 Visits

本次没有实做的功能

真实录音/Voice Session、真实附件上传、短信/电话/传真、CME Claim、Community Complete Setup、Care Team 邀请、公开分享。这些动作会涉及权限、外部发送、身份展示或账户状态变化。
